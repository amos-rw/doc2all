When each thing is removed

File contents (uploads and results)After 24 hours, or at once when the user presses Delete
File records, jobs, reports, findings (the history)When the user removes them from History, or deletes the account
One-time codesAfter use or after 10 minutes
SessionsAt sign-out, or after 30 minutes idle
Attempt countersAfter 24 hours
Users, passkeys, known devices, noticesWhen the account is deleted
Audit logStays. It never holds a name, an email, a file name or file content

Who can touch the database

The appReads and writes the tables. On the audit log it can only add and read
The setup accountOwns the tables. Used only to create or change them, never while the app runs
The sandbox runnerNo access at all

SR-19SR-20

Five decisions

  1. Database: Use PostgreSQL.It can let the app add and read audit lines but never change them. SQLite cannot limit one table like that.
  2. New device notice: Add one more needed cookie that holds a random value.Without it the app cannot know a device is new. The Privacy screen would list three cookies.
  3. History: Keep the file name in History after the content is deleted, until the user removes it.The user sees what happened. The name can itself be personal, so it can be removed.
  4. Administrator: Show ids on the Records screen, never file names.A file name can reveal what a document is about.
  5. Audit log: Give each line the fingerprint of the line before.Someone with database access who changes a line can then be noticed.
